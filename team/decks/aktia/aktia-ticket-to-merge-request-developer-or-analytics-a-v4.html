Technical solution architecture

The agent drafts, a person merges. One loop inside Aktia's tenant, with no path around review.

1 · AKTIA'S INPUTS
Analytics ticket in your ticket system. Never from chat
Data model and conventions in your Git repo
Analytics layer in dev, masked where needed. No Temenos or production access
→
2 · AGENT IN YOUR TENANT
Data engineer agent plans, writes code and tests
Model behind one swappable interface
Unclear ticket: questions back, no guessing
→
3 · REVIEW AND LOG
Review agents and tests on every change. Failures go back
Schema-dependency paths flagged (CODEOWNERS)
Auditor agent logs every action to your log store, append-only
→
4 · AKTIA DECIDES
Pull request: diff, test evidence, reasoning
Named reviewer, never the ticket requester, approves or rejects
Only a person merges. Deploy via your pipeline
PERMISSIONS: Aktia-issued identities, secrets in your vault. The agent writes only to its own branches and a dev schema, holds no production credentials, cannot approve, merge or change branch rules (owned by Aktia admins). Kill switch on its identity.
  • Your stack, honestly: the RFP says "current data setup" and "public cloud"; ticket system and Git host are assumed. Week 1 confirms all three. On Snowflake + dbt we deploy our agent team. On another stack the agent is a new build, and scope is re-agreed at the gate. You can stop there.
  • Out of scope: ML models or anomaly detection, new BI tools, extra use cases, any change to Temenos Transact. Only ticket → code → tests → pull request.
